# Demo 3 analysis: what the gate changes, what it costs, where it fails

The approach and setup are described in [DEMO3.md](DEMO3.md). Every table in this document is generated by
`scripts/demo3_report.py` into [results/demo3](../results/demo3/README.md), which also defines each metric.
Test split, seed 0, Demo 2 settings. † = a Demo 2 baseline that the experiment handed the true target; a
deployed system has to detect the target, which is what the gate (G) does.

## Summary

* **The gate protects as well as the best baseline for each threat, without being told the target, and leaves
  benign requests alone.**
  * Exact copies (SD 1.4): 33% → 6% copied, and only 3% of ordinary captions are changed. Best safe-utility
    F1: 0.639, vs 0.624 for the best baseline (D2a).
  * Characters (mean over the four attacks): 37% → 2% on SD 1.4, 33% → 7% on Playground v2.5, 26% → 3% on
    PixArt-α. The oracle D4+D2b† reaches 1%, 5% and 3%.
  * Styles (SD 1.4): 22% → 8% attributed, the same as the oracle D2b-name†, and no public-domain request is
    changed.
* **The vanilla blocklist fails both ways.** It stops a character's name, but not a description or keywords
  (33–38% still drawn). It also refuses 15% of public-domain style requests.
* **First trade-off: protection vs. on-prompt images.** G's character mitigation keeps only 34% (SD 1.4) to
  53% (Playground) of protected character images on-prompt. The rewrite-only ablation (G-rw) has a higher F1
  on every model, but it leaks 13–15% of characters (vs 2–7% for G) and widens the gap between rights holders.
* **Second trade-off: runtime and the output check.** Screening without the output check (G-pre) adds 4–13%
  to a benign request on Playground and SD 1.4, and 20% on PixArt, whose render takes only 1.3 s. The output
  check halves the leak under the worst attack. But its threshold was set on SD 1.4, and on Playground and
  PixArt it re-renders about a quarter of benign near-miss requests.

* **G gives the most protective baseline's protection without the oracle.**

  * The gate never refuses anything.

    the name.
* **On F1, G is best for exact copies, tied for best on Playground, and behind the rewrite (D4) on SD 1.4
  and PixArt characters.** Section 2.1 explains why. Most F1 intervals overlap. The clear separations are
  against V0, C1, and D4+D2b† on SD 1.4.

## 2. Trade-offs

### 2.1 Which character mitigation? Protection vs. on-prompt (ablation G-rw)

G uses He et al.'s strongest character mitigation for a detected character: the LLM rewrite plus the
character's name/keyword negative prompt (D4+D2b). G-rw is the same gate with the rewrite alone. It needs no
new images: each G-rw image is D4's image of the same request and seed, because the gate and D4 used the same
rewrite in 100% of cases. G-rw was added after we saw the test results, so it is an ablation, and G stays the
method.

| model | guardrail | mean / worst leak | risky on-prompt | benign served | F1 [95% CI] | largest rights-holder gap |
|---|---|---|---|---|---|---|
| SD 1.4 | D4 (rewrite, every request) | 9 / 18% | 50% | 74% | 0.576 [0.49, 0.66] | 19 pts |
| | D4+D2b† (every request) | 1 / 3% | 34% | 59% | 0.428 [0.34, 0.51] | 4 pts |
| | G-rw (gate, rewrite only) | 13 / 18% | 48% | 93% | 0.593 [0.49, 0.68] | 13 pts |
| | G-pre (gate, rewrite + negative prompt) | 5 / 10% | 36% | 91% | 0.494 [0.40, 0.59] | 8 pts |
| | **G** (+ output check) | 2 / 5% | 34% | 91% | 0.494 [0.39, 0.59] | 4 pts |
| Playground v2.5 | D4 | 11 / 23% | 55% | 89% | 0.663 [0.57, 0.74] | 32 pts |
| | D4+D2b† | 5 / 11% | 53% | 87% | 0.653 [0.56, 0.73] | 14 pts |
| | G-rw | 13 / 21% | 55% | 98% | 0.674 [0.57, 0.76] | 37 pts |
| | G-pre | 9 / 15% | 53% | 98% | 0.663 [0.56, 0.75] | 21 pts |
| | **G** | 7 / 10% | 53% | 96% | 0.664 [0.57, 0.75] | 14 pts |
| PixArt-α | D4 | 14 / 29% | 52% | 96% | 0.644 [0.54, 0.73] | 24 pts |
| | D4+D2b† | 3 / 8% | 46% | 94% | 0.611 [0.51, 0.70] | 7 pts |
| | G-rw | 15 / 28% | 49% | 94% | 0.614 [0.51, 0.70] | 30 pts |
| | G-pre | 5 / 15% | 45% | 94% | 0.590 [0.48, 0.68] | 11 pts |
| | **G** | 3 / 8% | 44% | 94% | 0.590 [0.48, 0.69] | 7 pts |

* **The negative prompt buys protection and costs on-prompt images.**
  * Going from the rewrite alone (G-rw) to rewrite + negative prompt (G-pre) cuts the mean leak from 13% to
    5% on SD 1.4.
  * It also lowers the share of protected-character images that still show the requested subject, from 48%
    to 36%.
  * He et al.'s keyword negative prompt suppresses the generic entity as well as the character (the mouse in
    a Mickey request, the yellow electric creature in a Pikachu request), which is the subject the on-prompt
    judge checks for.
* **Safe-utility F1 weighs a leak and an off-prompt image equally, so it prefers the rewrite alone.**
  * G-rw has the higher F1 on every model.
  * The differences are inside the 95% intervals.
* **The negative prompt also evens out who is protected.**
  * Under the rewrite alone, Marvel characters leak 21–39% across the three models.
  * G's largest gap between rights holders is 4 / 14 / 7 points, vs 13 / 37 / 30 for G-rw.
* **Which operating point is right depends on the cost of a leaked character relative to an off-prompt image.**
  * A provider facing infringement claims would keep G.
  * A provider that weights utility more would pick G-rw.
  * Either way, detection is what lets the mitigation leave benign requests alone: 91–98% of near-miss
    requests are served, vs 59–89% for always-on D4 / D4+D2b.

### 2.2 The output check (G vs. G-pre)

| | worst-attack leak: G-pre → G | mean: G-pre → G | benign near-miss requests re-rendered | s / benign request: D0 · G-pre · G |
|---|---|---|---|---|
| SD 1.4 | 10% → 5% | 5% → 2% | 2% | 5.02 · 5.68 · 5.86 |
| Playground v2.5 | 15% → 10% | 9% → 7% | 24% | 6.26 · 6.53 · 8.44 |
| PixArt-α | 15% → 8% | 5% → 3% | 26% | 1.30 · 1.56 · 2.33 |

* **The output check halves the leak under the worst attack.**
  * It catches 8–18% of the description and keyword lures that the text screen misses (Section 3).
  * The CLIP pass itself costs 0.02–0.03 s per image.
* **Its threshold does not transfer across models.**
  * It was calibrated on SD 1.4 dev images, where it flags 1.9% of benign images.
  * On Playground and PixArt it fires on 24–26% of benign near-miss images. Each firing costs a second
    render, which takes G's benign-request time from +4% to +35% (Playground) and from +20% to +79%
    (PixArt).
  * The re-rendered images mostly stay on-prompt (Playground: 98% → 96% served), so the cost is time, not
    utility.
* **The fix is cheap:** calibrate the threshold per model on that model's dev images, as we did for SD 1.4.

### 2.3 Runtime

The gate's runtime is made up of:

* the concept screen: 0.12 s per request (Qwen3-8B on an RTX 4090);
* on SD only, the memorization scan: 1.1–1.5 s on an RTX 2080 Ti;
* the LLM rewrite: about 1.6 s, only when a character is detected;
* the output check: 0.02–0.03 s, plus a second render when it fires.

Per risky request on SD 1.4 that totals +27% (exact copies) to +62% (characters) over no guardrail, because
most character requests are rewritten. For comparison, D4 adds 29–31% to every request. On a benign request,
G costs +11–17% on SD 1.4, where the memorization scan dominates, and G-pre costs +4% on Playground. On a
laptop (Apple M2), the live demo's scan takes 19 s for a caption and its three candidate templates.

### 2.4 Memorized captions on SD 2: the template order does not transfer

The order in which the gate tries templates (D2a, then D3, then D1) came from SD 1.4 dev data, where D2a keeps
the most of the caption. On SD 2, D2a stays on-prompt less often than D1 (36% vs 46%). G picked D2a for 78 of
100 captions, so it matches D1's protection (0 copies) at a lower on-prompt rate (35% vs 46%).

The memorization scan also flags 93 of 100 SD 2 captions, although only 8% of them are copied without a
guardrail. SD 2 memorizes these captions only weakly (template-style memorization), so the scan intervenes far
more often than needed. Per-model template order and thresholds are the fix.

## 3. Error analysis: what still gets through

**Concept-screen hit rate by attack.** This is text only, so it is the same for every model:

| attack | flagged by the concept screen | additionally caught by the output check |
|---|---|---|
| name (plain request) | 100% | 0% |
| misspelling | 82% | 0–3% |
| 60-word description, no name | 77% | 8–15% |
| keyword lure | 54% | 8–18% |

Keyword lures are the hardest attack for a text screen: a few cue words such as "red cap, mustache, plumber,
overalls" rarely spell out a single character for the LLM. The same cues are often enough for the model to
draw the character, though, which is why the image-side check matters most for this attack. The keyword lures
that got past both signals name the franchise, not the character ("toy, Toy Story, Disney, Pixar" for Buzz
Lightyear; "Disney, seven dwarfs" for Snow White). The screen's closed list contains only character names, so
adding franchise names to it is a cheap fix.

**Failures under G** ([gate_errors.md](../results/demo3/gate_errors.md)), counting images where the judge
still names the character, the copy survives, or the artist is still attributed:

| run | items still failing | cause |
|---|---|---|
| characters, SD 1.4 | 3 of 39 | 2 images missed by both screen and check (keyword lures for Buzz Lightyear and Maleficent); 1 detected, but the mitigation was not enough |
| characters, Playground | 6 of 39 | 7 images detected but not enough (Marvel characters, Batman, Yoda); 3 missed by both (Buzz Lightyear, Snow White); 1 Yoda description matched to the wrong character (Doraemon) |
| characters, PixArt | 4 of 39 | 4 images detected but not enough |
| exact copies, SD 1.4 | 4 of 130 | all flagged; the chosen template (D2a) scored below the threshold but the copy survived (verbatim memorization) |
| exact copies, SD 2 | 0 of 100 | |
| styles, SD 1.4 | 12 of 120 | 11 images detected, but the name as negative prompt was not enough; 5 misspellings missed; 1 matched to a character (Yoda) |

* **Most residual failures are mitigation failures, not detection failures.** The next step is escalation:
  when the output check sees the character on a mitigated image, apply a stronger rung instead of only adding
  a negative prompt.
  * For verbatim memorization, the template's own memorization score is not a sufficient check, so the
    escalation there is to D1 or D4.
* **Benign false positives.**
  * Concept screen: 4 of 54 near-miss requests (7%). The near-miss set is, by design, the generic version of a
    protected character, e.g. "a cartoon mermaid".
  * Memorization scan: 3 of 100 ordinary captions; the target on the dev split was 2%.

## 4. Subgroups: is protection equal?

* **Characters by rights holder.**
  * Without a guardrail, the largest gap is 38 points on SD 1.4 (Pokémon 50% vs 12%) and 36–38 points on the
    other two models, where Marvel is the most exposed (57% on Playground, 50% on PixArt).
  * G narrows the largest gap to 4 / 14 / 7 points (SD 1.4 / Playground / PixArt). The oracle D4+D2b reaches
    the same.
  * The rewrite alone leaves 19–32 points (D4) or 13–37 points (G-rw).
* **Characters by origin (US vs. Japan).** Small without a guardrail on SD 1.4 (1 point), 11–15 points on the
  other models. G's largest is 10 points (Playground).
* **Memorized captions by memorization type.**
  * Without a guardrail, 43% of verbatim-memorized (VM) captions are copied vs 2% of template-memorized
    (TM): a 41-point gap.
  * Under G the gap is 9 points, and all remaining failures are VM (Section 3).
* **Artists by group** (attribution above chance, living vs. deceased-in-copyright). G's gap is 3 points, vs
  5 for no guardrail and 20–23 for the instruction templates D1 and D3.

## 5. Outside the Stable Diffusion family

Playground v2.5 is an SDXL-architecture model from another company, trained on other data. PixArt-α is a
diffusion transformer with a T5 text encoder. Both behave like SD 1.4 for characters:

* without a guardrail, 67% and 46% of named characters are recognized;
* the blocklist stops names, but lures still get through: 33% and 36% leak under the worst attack;
* G reaches the oracle's level: worst attack 10% and 8%, vs 11% and 8% for D4+D2b†.

The memorization screen needs a UNet's first-step noise prediction, so it is off on these models, and we did
not test exact copies on them. Only the output-check threshold failed to transfer (Section 2.2).

## 6. How much to trust these numbers

* **On-prompt judge.** VQAScore with Qwen2.5-VL-7B separates matched from mismatched prompts on the same
  images.
  * It works well for captions, styles and near-miss requests: AUC 0.93–0.99, false-yes rate 0–11%.
  * It is weaker for a character's generic subject (AUC 0.72–0.78) and for SD 2 captions (0.79). Treat
    character on-prompt differences of a few points as noise.
  * A hand-labelled, balanced sample of 120 images is the second check
    (`scripts/onprompt_sample.py`). Its agreement and Cohen's kappa go into the judge-validation table once
    the labels are in.
* **One seed.** The Demo 2 grid was re-rendered with seed 0 under the class GPU cap. The re-render matches the
  committed two-seed Demo 2 results closely:
  * median absolute difference 0.3 points, largest 5 points;
  * rank agreement 0.86–1.0 per run.
* **Uncertainty.** The 95% intervals resample items. Most F1 differences between G, G-rw and D4 lie inside
  them.
* **No test leakage.** The screen prompt, its worked examples, the memorization threshold and the
  output-check threshold were all set on the dev split. G-rw is the one choice made after seeing test
  results, and it is reported as an ablation.
* **A bug we found and fixed before these numbers.** The output check was also applied to the G-pre ablation
  (so G-pre equalled G). Details are in [DEMO3.md](DEMO3.md).

## 7. Next steps

1. Calibrate the output-check threshold and the template order per model on that model's dev images, and add
   franchise names to the screen's closed list.
2. Escalate when a mitigated image still shows the protected content (stronger template, rewrite + negative
   prompt) instead of stopping after one second render.
3. Make the character mitigation a stated policy choice (G vs. G-rw), set from the relative cost of a leak
   and an off-prompt image.
4. Add a benign caption set for SD 2, so F1 can be computed for exact copies there.
